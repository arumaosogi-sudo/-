# ขั้นตอนการพัฒนา: กระปุกห้องเรียน

เอกสารนี้สรุปว่าโปรเจกต์ถูกสร้างอย่างไร ตั้งแต่เก็บความต้องการจนถึงขึ้นระบบจริง มีการตัดสินใจอะไรบ้างและเพราะอะไร รวมถึงปัญหาที่เจอและวิธีแก้

## 1. ที่มาและเป้าหมาย

ครูประถมหลายโรงเรียนรับฝากเงินออมจากนักเรียนทุกเช้าแล้วจดลงสมุด วิธีนี้มีปัญหาคือ:
- รวมยอดผิดง่าย และสมุดอาจหาย
- ผู้ปกครองไม่รู้ยอดเงินของลูกจนถึงปลายเทอม
- ครูต้องเสียเวลาตอบคำถามเรื่องยอดเงินทีละคน

**เป้าหมาย:** แอปบนมือถือที่ครูบันทึกฝาก-ถอนได้ในไม่กี่วินาที ยอดเงินถูกต้องเสมอ และผู้ปกครองดูยอดของลูกได้เองผ่าน LINE

**ขนาดระบบที่ออกแบบไว้:** ครู 30–50 คน นักเรียนประมาณ 1,000 คน และต้องใช้บริการฟรีทั้งหมด

## 2. วิธีทำงาน

พัฒนาแบบแบ่งเป็น Phase ทีละขั้น ทุก Phase จบด้วยการทดสอบในเบราว์เซอร์จริง รายงานผลให้ผู้ใช้ (ครู) แล้วรับความเห็นก่อนเริ่ม Phase ถัดไป

| Phase | งานที่ทำ | ผลลัพธ์ |
|---|---|---|
| 0. วางแผน | เก็บความต้องการ เลือกเครื่องมือ (ผู้ใช้ไม่ต้องการ Supabase จึงเลือก Neon + Drizzle + Better Auth) | แผนงานและ stack |
| 1. ตั้งโปรเจกต์ | Next.js 16, Tailwind 4, shadcn/ui, Drizzle, ฐานข้อมูลในเครื่องด้วย PGlite | รันได้ทันทีโดยไม่ต้องติดตั้งฐานข้อมูล |
| 2. ระบบ Login | Better Auth, `proxy.ts` กันหน้าที่ต้อง login | สมัคร/เข้าสู่ระบบได้ |
| 3. ห้องเรียนและนักเรียน | สร้าง/แก้/เก็บห้อง, วางรายชื่อนักเรียนหลายคนพร้อมกัน | จัดการห้องเรียนได้ |
| 4. ฝาก-ถอนเงิน | ปุ่มฝากด่วน 5/10/20/50/100, รับเศษสตางค์, ยกเลิกรายการ, ประวัติรายเดือน | หัวใจของแอป |
| 5. ตั้งค่า | ธีมสว่าง/มืด, บัญชีผู้ใช้, ตั้งเวลาส่งแจ้งเตือน | หน้าตั้งค่า |
| 6. LINE ผู้ปกครอง | ผูกบัญชีด้วยรหัส 6 หลัก + ปุ่มยินยอม, Webhook, ตัวส่งอัตโนมัติ | ผู้ปกครองได้ยอดใน LINE |
| 7. พร้อมใช้งานจริง | PWA, ส่งออก Excel, ส่งยอดรายคน, deploy ขึ้น Vercel + Neon | ใช้งานบนมือถือได้จริง |
| 8. รองรับครูหลายคน | LINE Login อย่างเดียว, ครูกรอก key ของ OA ตัวเอง (เข้ารหัสเก็บ), Webhook แยกต่อ OA | รองรับครู 30–50 คน |
| 9. การ์ดรายสัปดาห์ | ยอดคงเหลือ + รายการสัปดาห์นี้ (เริ่มนับใหม่ทุกวันจันทร์), ปุ่มลัด | ผู้ปกครองดูยอดง่ายขึ้น |
| 10. แอป Android | ห่อเว็บเป็นแอปด้วย TWA (Bubblewrap) แล้วเซ็นแอป | ไฟล์ APK ให้ดาวน์โหลด |
| 11. ปรับจากการใช้จริง | แก้ยอดรวมห้องที่ยังนับนักเรียนที่ย้ายออก, เพิ่มขั้นยืนยันก่อนบันทึกเงิน | แอปที่ปลอดภัยต่อความผิดพลาด |

## 3. การตัดสินใจสำคัญ

### ข้อมูลเงิน
- **ไม่เก็บยอดเงินเป็นตัวเลขที่แก้ไขได้:** ยอดคำนวณจากผลรวมรายการทั้งหมดเสมอ จึงไม่มีทางที่ยอดกับประวัติจะไม่ตรงกัน
- **เก็บเงินเป็นสตางค์ (จำนวนเต็ม):** กันทศนิยมคลาดเคลื่อน เช่น 0.1 + 0.2
- **แก้รายการโดยบันทึกรายการกลับ ไม่ลบรายการเดิม:** ตรวจสอบย้อนหลังได้ และฐานข้อมูลบังคับว่าแต่ละรายการถูกกลับได้ครั้งเดียว
- **ล็อกแถวนักเรียนก่อนถอน (`SELECT … FOR UPDATE`):** ถ้ากดถอนพร้อมกันสองเครื่อง ยอดก็ไม่ติดลบ
- **มีขั้นยืนยันก่อนบันทึก:** แสดงยอดก่อนและหลังบันทึก เพิ่มเข้ามาตามคำขอของครูหลังทดลองใช้

### ความปลอดภัย
- ทุก query ผ่านชั้นกลาง (`src/server/`) ที่ตรวจว่าข้อมูลเป็นของครูคนนั้น ถ้าครูเปิดลิงก์ของห้องคนอื่นจะได้หน้า 404
- key ของ LINE OA เข้ารหัสด้วย AES-256-GCM ก่อนเก็บลงฐานข้อมูล
- Webhook ทุกครั้งตรวจลายเซ็น HMAC ด้วย secret ของ OA นั้น ๆ
- ตัวส่งอัตโนมัติต้องมี `CRON_SECRET` และเรียกซ้ำก็ไม่ส่งซ้ำ
- ผู้ปกครองต้องกดยินยอมก่อนผูกบัญชีกับนักเรียน

### ต้นทุน (ใช้บริการฟรีทั้งหมด)
- **Neon ฟรี 0.5 GB:** นักเรียน 1,000 คนฝากทุกวันใช้พื้นที่ประมาณ 60 MB ต่อปี
- **LINE OA ฟรี 300 ข้อความ/เดือน/OA:**
  - ให้ครูแต่ละคนใช้ OA ของตัวเอง โควตาจึงไม่ถูกแชร์กันทั้งโรงเรียน
  - เมื่อผู้ปกครองกด "ยอดเงิน" เอง ระบบตอบด้วยข้อความตอบกลับ ซึ่งไม่นับโควตา
- **Vercel Hobby:** cron รันได้วันละครั้ง ระบบจึงเช็กเองว่าครูคนไหนถึงรอบส่ง

## 4. ปัญหาที่เจอและวิธีแก้

| ปัญหา | สาเหตุ | วิธีแก้ |
|---|---|---|
| ข้อมูลในเครื่องหายเป็นระยะ | PGlite ถูกเปิดสองโปรเซสพร้อมกัน (โค้ดเก่าที่ค้างใน cache ของ Turbopack ยังเปิดฐานข้อมูลอีกตัว) | ย้าย migration ไปรันก่อน dev, เพิ่มไฟล์ล็อก, ให้ `db` เชื่อมต่อเมื่อถูกใช้ครั้งแรกเท่านั้น |
| ช่องในฟอร์มถูกล้างเมื่อกรอกผิด | React 19 รีเซ็ตฟอร์มหลัง action ทำงานเสร็จ | ส่งค่าที่กรอกกลับมาจาก server หรือใช้ฟอร์มแบบ controlled |
| SQL error "ambiguous id" | Drizzle ตัดชื่อตารางออกใน subquery ที่อ้างถึง query ชั้นนอก | เขียน SQL ส่วนนั้นเองโดยระบุชื่อตารางเต็ม |
| ยืนยัน Channel ID ของ OA ไม่ได้ | LINE ไม่มี API ตรวจ token แบบ long-lived กับ Channel ID | ระบุ OA ด้วย bot userId จาก `/v2/bot/info` |
| ผู้ปกครองส่งข้อความแล้ว OA ไม่ตอบ | Webhook ใน LINE ยังชี้ไป URL เก่า หรือสวิตช์ "Use webhook" ปิดอยู่ | ตั้ง Webhook ผ่าน API ให้อัตโนมัติ, หน้าตั้งค่าเช็กสถานะสดและมีปุ่มซ่อม |
| ระบบจริงขึ้น error 500 | การ claim โปรเจกต์ Neon เปลี่ยนรหัสผ่านฐานข้อมูล | อัปเดต connection string ใน Vercel แล้ว deploy ใหม่ |
| ยอดรวมของห้องยังนับนักเรียนที่ย้ายออก | query ยอดรวมไม่ได้กรองนักเรียนที่ถูก archive | นับเฉพาะนักเรียนในห้อง และหน้านำออกเตือนให้ถอนเงินคืนก่อน |
| สร้าง APK ไม่ผ่าน | Bubblewrap ต้องใช้ JDK 17 และโครงสร้าง Android SDK แบบเก่า | ติดตั้ง JDK 17 และสร้าง junction `tools` ไปที่ `cmdline-tools/latest` |

## 5. การทดสอบ

ทุก Phase ทดสอบแบบ end-to-end ในเบราว์เซอร์จริงกับฐานข้อมูลในเครื่อง ชุดทดสอบล่าสุด (A–O) ครอบคลุม:
- การบังคับ login และการกันไม่ให้เปิดข้อมูลของครูคนอื่น
- ฝาก/ถอน/ยกเลิก/กลับรายการ และความถูกต้องของยอดรวม
- นักเรียนที่ย้ายออก การกรองรายเดือน และไฟล์ Excel
- Webhook ของแต่ละ OA แยกกันจริง การ์ดรายสัปดาห์เริ่มนับใหม่วันจันทร์ และสิทธิ์ของ cron
- ขั้นยืนยันการฝาก-ถอน: กดยืนยันจึงบันทึก, กดแก้ไขแล้วค่าเดิมยังอยู่, ปิดหน้าต่างแล้วไม่มีอะไรถูกบันทึก, ยอดเกินถูกกันไว้ก่อนถึงขั้นยืนยัน

หลัง deploy ทุกครั้งจะทดสอบหน้าหลักและไฟล์ดาวน์โหลดบนระบบจริงอีกรอบ

## 6. สิ่งที่วางแผนต่อ

- สำรองข้อมูลอัตโนมัติรายสัปดาห์ (Neon แบบฟรีกู้ข้อมูลย้อนหลังได้แค่ไม่กี่ชั่วโมง)
- เพิ่มชุดทดสอบอัตโนมัติ: unit test ด้วย Vitest และ end-to-end ด้วย Playwright รันใน GitHub Actions
- ตัวส่งรายชั่วโมง (เช่น Upstash QStash) เพื่อให้ครูเลือกเวลาส่งได้จริง
- รายงานภาพรวมระดับโรงเรียน
